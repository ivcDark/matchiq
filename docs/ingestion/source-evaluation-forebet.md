# Оценка источника: Forebet (forebet.com)

**Дата проверки:** 2026-11-25. **Вердикт: не подходит как primary-источник.**

## Метод и ограничения проверки

- Прямые запросы `curl` с машины к `www.forebet.com` (включая `/robots.txt`, `/sitemap.xml`, `/en/terms-of-use`, страницы РПЛ) **все получают `HTTP 403` + `cf-mitigated: challenge`** (Cloudflare «Just a moment…», managed challenge с JS и Turnstile).
- Обход челленджа (подмена UA под Googlebot, headless-браузер, прокси) **не пробовался и не рекомендуется**: это противоречит условиям использования и хрупко.
- Поэтому содержимое страниц изучено по **снимкам Wayback Machine** (`web.archive.org`, `id_`-режим, сырой HTML): главная «today» от 2025-12-23, страница РПЛ от 2025-09-16, `robots.txt` от 2026-05-03, ToS от 2026-05-03, `sitemap.xml` от 2025-01-04. Это отражает структуру сайта, но не живое состояние. Страницы матчей (`/en/football/matches/...`) в архиве не найдены — раздел про матч помечен как **не проверено**.
- Rate-limit измерить нельзя: до контента не дойти.

## 1. robots.txt и условия использования

- `robots.txt` (снимок): `User-agent: *` / `Disallow:` — формально разрешено всё, sitemap не указан.
- ToS (редакция от 17.10.2024), п. 4 и 7: запрещено **воспроизводить, дублировать, продавать, использовать в коммерческих целях** любую часть контента без письменного разрешения; весь контент (прогнозы, статьи, картинки) защищён авторским правом, копирование и распространение без разрешения запрещены. Прямого слова «scraping» нет, но MatchIQ — публичный продукт, а значит это коммерческое/публичное использование. П. 5: доступ могут ограничить в любой момент.
- Вывод «на глаз»: **robots.txt не запрещает, ToS — запрещает** для нашего сценария (хранение и показ данных в продукте). Нужно письменное разрешение либо не использовать.

## 2. Антибот

- Cloudflare managed challenge на **всех** путях, включая `robots.txt` и `sitemap.xml`. Без выполнения JS/Turnstile контента нет (ответ 403, ~5.5 КБ страницы-челленджа).
- Заголовки `Critical-CH`/`Accept-CH` (client hints) — характерно для усиленной проверки.
- Для Go-коллектора это значит: нужен headless-браузер/solver-сервис или резидентные прокси, постоянная гонка с антиботом. Для production-пайплайна это неприемлемый риск стабильности.
- Cookies: сайт сам ставит cookie (`getCookie` в JS — часовой пояс, формат коэффициентов), но решающим является `cf_clearance`.

## 4. Покрытие

- Россия (по снимкам): РПЛ (`premier-liga`), 1-й дивизион (ФНЛ, `1-division`), ФНЛ-2 (группы A/G), ПФЛ (5 зон), Кубок, Суперкубок, женская Высшая лига, молодёжная лига.
- Всего на странице «today» ~190 слагов стран/регионов, сотни лиг (в т.ч. низшие дивизионы и юношеские); ~1000–1500 матчей в день. Покрытие **широкое** — это сильная сторона.
- История: селектор сезонов в РПЛ — 25 сезонов (с 2000/01) для таблиц/результатов.
- Нужно заметить: Forebet — сайт прогнозов, лиги представлены тем, где есть odds/модель; для «матчевых» сущностей полнота исторических данных не гарантирована.

## 6. Навигация и API

- Путь: `/en/` → список стран (меню) → `/en/<country-prefix>` → соревнование → вкладки `standing`/`results`/`fixtures`/`form`/`stat`/`stat-trends` → сезон `/<tab>/<yyyy-yyyy>` → строка матча → `/en/football/matches/<slug>-<id>`.
- Публичного API нет. Данные в таблицах — серверный HTML (`schema.org/SportsEvent`: `name`, `startDate`, `homeTeam`, `awayTeam`, `location`), т.е. парсится DOM без JS — **если бы не Cloudflare**. Live и детали грузятся XHR (`getFTEvents`, `getHodd`, `getstag`).
- `sitemap.xml` (снимок): ~2350 URL, но это страницы лиг/стран и видов спорта, **URL матчей и команд нет**. В `robots.txt` не объявлен. Обход «страна → лига → сезон → результаты → матч» — единственный путь.
- Мобильная версия `m.forebet.com` — тоже под защитой (не проверялось).

## 7. Качество данных

- Язык: EN (+RU и ещё 10 языков через `/en/`-аналоги). Названия команд — «сайтовые» варианты, не канонические.
- Live: есть (минута, счёт, live-коэффициенты), частота обновления — XHR, неизвестна; для нас не критична (live — позже).
- Полнота: составов и xG на уровне списков нет; нет игроков/судей/стадионов как сущностей; нет team-страниц с id.
- Время: показывается в часовом поясе пользователя (cookie/настройка), нужно фиксировать `UTC`.

## 8. Вердикт

**Не подходит как primary.** Причины: (1) Cloudflare challenge на каждом запросе, надёжный Go-коллектор без обхода защиты невозможен; (2) ToS запрещает коммерческое использование/воспроизведение контента без письменного разрешения; (3) нет id команд/лиг/игроков/судей, нет составов и xG — не хватает под модель «страны → соревнования → сезоны → матчи → события/стата/составы»; (4) это сайт прогнозов, а нам нужны факты, вероятности считаем сами.

**Годится как побочный:** сверка расписания/результатов (по числовому id матча) и сравнение наших вероятностей с их прогнозами — **только вручную/через разрешение**, не в пайплайне.

### Главные риски
1. Антибот: любая интеграция будет нестабильна и требует обхода защиты.
2. Юридический: запрет коммерческого воспроизведения без письменного согласия.
3. Нет id команд → сложный матчинг в `team_aliases`.
4. Слабая детализация матча (составы/xG/события) — модель и страницы матча не наполнить.
5. Непоследовательные slug-префиксы стран — нужна ручная карта.

### Альтернативы того же класса (EN, менее известные)
Не проверялись с машины в этом заходе — это ориентиры для следующей оценки:
1. **FBref (Sports Reference)** — xG/продвинутая стата, составы, судьи, стадионы, стабильные id (`/en/matches/<8hex>`, `/en/squads/<id>`), но слабое покрытие РПЛ (стата ограничена, есть Cloudflare, строгий rate-limit ~20 req/min, ToS ограничивает).
2. **Soccerway** (Perform) — страны/лиги/сезоны/матчи/составы/события, числовые id в URL, РПЛ с глубокой историей; сайт частично на JS, возможен антибот.
3. **ESPN FC / Sofascore (неофициальный JSON)** — удобный JSON, широкие id, но неофициальный API и ToS-риск; Sofascore — самый полный по составам/событиям/xG, но нужны осторожность и, скорее всего, платный API (API-Football / Sportmonks) как primary.

Рекомендация: для primary — платный API (API-Football, Sportmonks, football-data.org для старта), парсеры — как дополнительные источники. Схема `external_ids` + `team_aliases` это допускает (см. `docs/database/README.md`).

# API-Football (api-sports) vs UI MatchIQ: покрытие

**Дата проверки:** 2026-11-25. **Вердикт: хватает с оговорками.** Каркас матча, составы, события, рейтинги игроков, таблица и профили закрываются целиком. Не закрываются «продвинутая» часть вкладки «Статистика» (большая часть xG-секций и ряд метрик атаки/защиты), статистика по таймам до сезона 2024, погода, судья как сущность и сроки возвращения травмированных.

## Метод и ограничения проверки

- **Ключа API у нас нет, живых вызовов не было.** `https://v3.football.api-sports.io/status` отвечает JSON «Missing application key», то есть хост доступен, но данных без ключа нет. Сайт `www.api-football.com` (документация, pricing, coverage, `openapi.yaml`) за Cloudflare-челленджем (`403`), поэтому читал **копии Wayback Machine** официальных страниц. Обход челленджа не пробовал.
- Источники:
  - **Официальный OpenAPI v3.9.3** (`/public/doc/openapi.yaml`, снимок 2025-11-02): параметры, описания и примеры ответов по всем эндпоинтам. Это главный источник.
  - **Coverage list** (снимок 2025-10-15, «1212 Leagues & Cups»): матрица по лигам, в том числе все соревнования России.
  - **Pricing** и **Terms** (снимки 2026-02-01).
  - Для сверки xG и таймов — сторонние описания API (Scalekit, Lodol, EdgeFinder-доки) и статья в официальном блоге про `/fixtures/players`.
- Снимки старше «сегодня» на 3–12 месяцев, API мог измениться. Всё, что ниже помечено **«проверить»**, надо подтвердить первым запросом с ключом (план проверки — в конце).
- Лига РПЛ: по общеизвестному id `235` (подтвердить через `/leagues?country=Russia`). Кубок России и ФНЛ — отдельные лиги.

## 1. Что покрывает API для России (coverage, снимок 2025-10-15)

Колонки coverage: события, составы, статистика матча, статистика игроков в матче, предсказания, коэффициенты, сезонная статистика игроков, топ-бомбардиры, таблица.

| Лига | События | Составы | Стат. матча | Стат. игроков в матче (рейтинги) | Predictions | Odds | Сезон. игроки | Топ-бомб. | Standings |
|---|---|---|---|---|---|---|---|---|---|
| **РПЛ** | да | да | да | **да** | да | да | да | да | да |
| Кубок России | да | да | да | **нет** | да | да | да | да | **нет** |
| ФНЛ (1st Division) | да | да | да | **нет** | да | да | да | да | да |
| ФНЛ-2, Суперкубок и ниже | да | да | нет/часть | нет | да | часть | часть | часть | часть |

Важное:

- **РПЛ закрыта полностью.** У **Кубка России** нет статистики игроков в матче (а значит **нет рейтингов, MOTM и минут**) и нет таблицы групп. А страница клуба и матча показывают именно кубок.
- В матрице нет колонки «injuries» и «xG» — их наличие по лиге смотрим в `/leagues` → `coverage` (поля `injuries`, `statistics_fixtures`, `statistics_players`, …). Coverage «не гарантирует 100% данных» (формулировка из доков), для не начатого сезона все флаги `false`.
- **Тарифы** (все эндпоинты и все лиги во всех планах): Free — 100 запросов/сутки и только часть сезонов (по сторонним данным, 2022–2024); Pro $19 — 7 500/сутки; Ultra $29 — 75 000; Mega $39 — 150 000. Лимит в минуту в пример не попал (есть заголовки `X-RateLimit-*`, превышение ведёт к блокировке).
- **Terms:** перепродажа данных запрещена; приложения на их данных — можно. Логотипы/фото/эмблемы приходят «для идентификации», права третьих лиц на нас (фото игроков и логотипы клубов — риск).

## 2. Что отдаёт API (по эндпоинтам)

| Эндпоинт | Что в ответе | Частота обновления (по докам) |
|---|---|---|
| `/fixtures` (`id`, `ids`, `live=all`, `league+season`, `date`, `round`, `last/next`) | id матча, `referee` (**строка**), дата, `status.short` (`NS`, `1H`, `HT`, `2H`, `ET`, `BT`, `P`, `LIVE`, `INT`, `SUSP`, `FT`, `AET`, `PEN`, `PST`, `CANC`, `ABD`, `AWD`, `WO`), `status.elapsed` + `extra`, `venue` {id, name, city}, `league.round` (строка «Regular Season - 15»), команды, `goals`, `score` {halftime, fulltime, extratime, penalty} | 15 с (live-запрос 1/мин) |
| `/fixtures/events` | `time` {elapsed, extra}, команда, игрок, `assist`, `type` (`Goal`, `Card`, `subst`, `Var`), `detail` (Normal Goal / Own Goal / Penalty / Missed Penalty / Yellow Card / Red Card / Substitution N / VAR-подтипы), `comments`; VAR с 2020/21 | 15 с |
| `/fixtures/lineups` | `formation`, **`coach`** {id, name, photo}, `startXI` и `substitutes`: id, имя, номер, `pos` (G/D/M/F), **`grid` «ряд:колонка»** (только у стартовых), цвета формы | 15 мин; составы появляются за 20–40 мин до матча |
| `/fixtures/statistics` (`half=true`) | на команду: Shots on/off Goal, Total Shots, Blocked, Shots insidebox/outsidebox, Fouls, Corner Kicks, Offsides, Ball Possession, Yellow/Red Cards, Goalkeeper Saves, Total passes, Passes accurate, Passes %, **`expected_goals`**, **`goals_prevented`**; с `half=true` ещё `statistics_1h` / `statistics_2h` | 1 мин |
| `/fixtures/players` | на игрока: `games` {minutes, number, position, **rating** («6.3»), captain, substitute}, offsides, shots {total, on}, goals {total, conceded, assists, saves}, passes {total, key, accuracy}, tackles {total, blocks, interceptions}, duels {total, won}, dribbles {attempts, success, past}, fouls {drawn, committed}, cards, penalty {won, committed, scored, missed, saved} | 1 мин |
| `/fixtures/headtohead` | список прошлых матчей двух команд (полные fixture-объекты, счёт и счёт 1-го тайма) | 15 с |
| `/standings` | rank, points, goalsDiff, **form** («WWWWW», 5), `description` (текст зоны), `all` / `home` / `away` {played, win, draw, lose, goals for/against}; параметров «после тура N» нет | 1 час |
| `/teams/statistics` (`league`, `season`, `team`, `date`) | сезонный срез: form-строка за сезон, fixtures/wins/draws/loses (home/away/total), **голы за/против по 15-минуткам** (`0-15` … `106-120`), under/over 0.5–4.5, clean_sheet, failed_to_score, biggest, penalty, **используемые формации**, **карточки по 15-минуткам** | 2 раза в день |
| `/players` (`team`, `league`, `season`, 20 на страницу) | профиль (firstname, lastname, age, birth, nationality, height «175 cm», weight, photo, injured) + сезонная статистика (appearences, lineups, minutes, **rating**, shots, goals, assists, passes, tackles, duels, dribbles, fouls, cards, penalty, substitutes in/out/bench) | несколько раз в неделю |
| `/players/squads` | текущий состав команды (id, имя, возраст, номер, позиция, фото) | несколько раз в неделю |
| `/players/topscorers`, `topassists`, `topyellowcards`, `topredcards` | **только топ-20** лиги | несколько раз в неделю |
| `/injuries` (`league+season`, `team`, `fixture`, `player`, `date`) | игрок, `type` (**`Missing Fixture`** / **`Questionable`**), `reason` (свободный текст), матч, на который это относится; данные **с апреля 2021** | 4 часа |
| `/sidelined` | история отсутствий игрока/тренера (тип, даты) | несколько раз в неделю |
| `/coachs`, `/venues`, `/leagues`, `/leagues/seasons`, `/fixtures/rounds` | тренер (возраст, национальность, карьера), стадион (адрес, город, вместимость, покрытие, фото), лига + `coverage` + сезоны (start/end/current), список туров | раз в день |
| `/predictions`, `/odds`, `/odds/live` | собственный прогноз API (проценты 1X2, under/over, сравнение, H2H), коэффициенты пре-матч/live | 1 час / 3 часа / 5–60 с |

Особенности, которые влияют на нас:

- `Red Cards`, `Fouls` и др. приходят как `null` и это может быть как «0», так и «нет данных» — нужно правило нормализации по лигам.
- `Ball Possession` и `Passes %` — строки с «%».
- В `fixtures` и `events` **нет текущего счёта в момент события** (считаем сами по порядку голов).
- Имена игроков в событиях/составах — сокращённые («D. Rodríguez»), полные имена — в `/players` (firstname/lastname).
- Имена команд/игроков — латиницей; русские переводы — наши (`name_i18n`).

## 3. Матч: поле UI → API

Легенда: **есть** (одно поле API), **частично** (есть с оговоркой), **нет**, **сами** (считаем из данных API или нашей БД).

### 3.1. Шапка и live

| Поле UI (`match.md`, `MockMatchCenter`) | Статус | Откуда / комментарий |
|---|---|---|
| Хозяева / гости, дата-время, тур, лига | **есть** | `/fixtures`; тур — строка `league.round`, номер нужно парсить («Regular Season - 15»), у кубка формат другой |
| Счёт (текущий / финальный) | **есть** | `goals`; `score.halftime` даёт счёт к перерыву, `extratime`/`penalty` — для кубков |
| Статус (ожидается / идёт / завершён) | **есть** | маппинг `status.short` → `matches.status` (см. 3.6) |
| Минута live, период (`minute`, `period`) | **есть** | `status.elapsed` (+`extra` для добавленного времени), период — по `1H/HT/2H/ET/BT/P` |
| Стадион | **есть** | `fixture.venue` (id, name, city); вместимость и покрытие — `/venues` |
| Судья | **частично** | **только имя строкой**, без id, страны и города: сущность `referees` придётся вести по нормализованному имени; поле «страна/город судьи» в шапке (`match.md`, п. 10) заполнить нечем |
| Погода (условие, °C, ветер) | **нет** | в API нет. Нужен внешний погодный источник по координатам стадиона (но координат тоже нет — `venues.lat/lng` позже, см. схему) |
| Посещаемость (`attendance`) | **нет** | — |
| Нейтральное поле (`is_neutral_venue`) | **сами** | по типу соревнования/раунду; в API флага нет |
| Форма палочками под именами | **сами** | из нашей БД завершённых матчей (`standings.form` из API — только общая) |

### 3.6. Разбивка по таймам (переключатель «Весь матч / 1 тайм / 2 тайм»)

| Поле UI | Статус | Комментарий |
|---|---|---|
| Статистика за 1-й / 2-й тайм | **частично** | `/fixtures/statistics?half=true` → `statistics_1h`, `statistics_2h`. **Только с сезона 2024.** Для РПЛ 2024/25+ ок, для более ранних сезонов таймов нет |
| Полнота таймовых метрик | **частично** | в примере в таймах есть удары, владение, передачи, угловые, офсайды, ЖК, xG; **фолы, сейвы, красные приходят `null`**; `goals_prevented` по таймам тоже `null` |
| Голы по таймам | **есть** | `score.halftime` и события |
| Карточки по таймам | **сами** | из событий |
| Live: «2 тайм доступен после 45′ (данные до 63′)» | **проверить** | отдаёт ли `half=true` данные по идущему матчу, в доках не сказано; общую статистику API отдаёт кумулятивно каждую минуту |
| Сумма таймов = матч | **частично** | в примере совпадает для ударов и угловых; владение и % пересчитывать нельзя (как и в UI), но `full_time` придёт отдельной строкой — схема это допускает |

## 5. Что критично для MVP match center

Критичность оценена для «Центра матча» (live/finished: Сводка + Статистика). Прогноз до матча от API почти не зависит.

| № | Пробел | Критичность | Что делать |
|---|---|---|---|
| 1 | **xG и всё, что вокруг** (xGOT, xGSP/xGC/xGFK/xGPen, xGOP, npxG, xA игрока, shot map). В API только командный `expected_goals` (+ `goals_prevented`), и он **не заявлен в списке доков** — виден в примере `half=true`. В UI это 4 секции из 8 и 12 рядов из 47, а xG/xGA/xPTS ещё и в «Последних 5» и «Дома / в гостях». | **высокая** | 1) первым делом проверить РПЛ 2024/25 и 2025/26: приходит ли `expected_goals`, на всех ли матчах; 2) если нет — решить: второй источник xG (платный xG-пакет Sportmonks, у них по changelog добавлена РПЛ в октябре 2026; Understat покрывает РПЛ, но это скрейпинг и ToS-риск — не проверялось) либо скрывать xG-секции; 3) в любом случае ряды без данных скрывать, а не показывать «–» в каждой строке; 4) xPTS считать только при наличии xG обеих команд |
| 2 | **Рейтинги и MOTM.** Есть для РПЛ (`games.rating`), **нет для Кубка России и ФНЛ**; алгоритм закрыт; у игроков без `rating` (малые минуты) — `null`; в live — только промежуточные | **высокая** для РПЛ — закрыта; **средняя** для кубка | Для кубка скрывать блоки «Лучшие игроки/MOTM/оценки» (UI уже умеет `rating = null` у live). Уведомить в `match.md`/`club.md`, что колонка «рейтинг» клуба в кубке пуста. Либо считать свой рейтинг (по минутам, голам, карточкам, как в моке) |
| 3 | **Статистика по таймам.** Только с сезона 2024; в таймах `null` для фолов, сейвов, красных, `goals_prevented`; поведение в live не описано | **высокая** (на ней вкладки 1/2 тайм и «Последние 5» по периодам) | Для сезонов до 2024 вкладки периодов выключать; фолы по таймам из UI убрать/«–»; карточки и голы по таймам считать из событий |
| 3б | **«Объёмные» метрики атаки/защиты:** атаки, опасные атаки, голевые моменты, штрафные, каркас, кроссы, вбрасывания, отборы выигранные, воздух/земля | **средняя** | 19 рядов без источника: либо убрать из MVP-макета, либо оставить пустыми для всех лиг; никаких «мок-значений» в проде |
| 4 | **Погода, посещаемость, судья как сущность** (id, страна, город) | **низкая/средняя** | Погода — отдельный источник (по координатам стадиона; нужна колонка `venues.lat/lng`, сейчас «позже»). Судья — ключ по нормализованному имени, страну не показывать |
| 5 | **Потери (травмы/дисквалификации).** Нет срока возвращения и даты начала; тип — только Missing/Questionable; покрытие РПЛ не подтверждено; обновление раз в 4 часа | **средняя** | В `player_absences` писать `since` = дата первой фиксации, `expected_return = null`; в UI не показывать срок. Проверить `coverage.injuries`; при отсутствии — ручной ввод/второй источник |
| 6 | **Таблицы кубка (группы)** и привязка команд к группам | **средняя** (страница клуба, не центр матча) | Считаем сами; формат `round` в кубке проверить |
| 7 | **Латиница и сокращения имён.** События и составы приходят как «D. Rodríguez»; UI показывает «Фамилия И.» по-русски | **средняя** | `players` по id из `/players`; русские имена/алиасы — наши (`name_i18n`, `team_aliases`). Для РПЛ — разовый ручной/полуавтоматический справочник |

## 7. План проверки (с ключом, не больше ~20 запросов Free-плана)

Free-ключ ограничен сезонами 2022–2024, поэтому тест идёт на **РПЛ 2024/25** (`season=2024`), когда уже должны быть и xG, и таймы. Параллельно нужен платный ключ на 1 день для сезона 2025/26 и актуального.

1. `GET /leagues?id=235&season=2024` и `season=2025`: `coverage` (в том числе `injuries`, `statistics_fixtures`, `statistics_players`), даты сезонов.
2. `GET /leagues?country=Russia`: id РПЛ, Кубка, ФНЛ.
3. `GET /fixtures?league=235&season=2024&status=FT&last=10`: структура, `round`, `referee`.
4. На 2–3 матча: `/fixtures/statistics?fixture=…&half=true`: есть ли **`expected_goals`**, `goals_prevented`, какие поля `null` по таймам.
5. На те же матчи: `/fixtures/players`, `/fixtures/events` (вторая жёлтая, формат замены), `/fixtures/lineups` (`grid`).
6. `GET /injuries?league=235&season=2024`: покрыты ли, как выглядит `reason`.
7. `GET /standings?league=235&season=2024`: `description` зон.
8. Кубок: `/fixtures?league=<id кубка>&season=…`: формат `round`, есть ли группы, есть ли рейтинги.
9. По результатам — обновить этот документ: заменить «проверить» на факт.

## 8. Итог

**Хватает с оговорками.** Страница матча в MVP (шапка, события, составы, расстановка, тренер, рейтинги, MOTM, форма, таблицы, голы по минутам, бомбардиры) закрывается API целиком для РПЛ. Оговорки: (1) xG не гарантирован и всё «продвинутое» вокруг него отсутствует; (2) 19 из 47 рядов статистики команды источника не имеют; (3) таймовая статистика только с 2024 и неполна; (4) для Кубка России нет рейтингов, минут и таблиц групп; (5) нет погоды, посещаемости, судьи с id; (6) потери — без срока возврата. Решение «брать API-Football как primary» это не отменяет (id, составы, события, рейтинги — сильные стороны), но **xG надо подтвердить первым делом** и держать вариант второго источника.

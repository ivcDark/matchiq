# Профиль игрока

**URL:** `/users/{id}` (числовой id; ник в URL не используется — в нём может быть кириллица и пробелы)  
**Статус:** MVP (макет на моковых данных)  
**Inertia:** `Users/Show` → общий компонент `Components/UserProfile.vue`  
**Доступ:** все (гость и авторизованный)

## Зачем страница пользователю

Посмотреть, как играет конкретный участник рейтинга: где он в таблице за разные периоды, какие турниры и типы событий предпочитает и какой прогноз у него сработал лучше всего. Переход — с `/leaderboard` (строка таблицы и карточки топ-3).

## Что на экране

1. **Ссылка «← К рейтингу»** → `/leaderboard`.
2. **Шапка:** аватар-инициалы, ник (метка «Это вы» для своего профиля), «На MatchIQ с {дата регистрации}», место в рейтинге за всё время («2 из 1 284») и очки.
3. **«Рейтинг»:** четыре плитки — Неделя / Месяц / Сезон / Всё время; в каждой место, очки, «угадано из прогнозов · точность %». У плитки «Сезон» подпись текущего сезона («2026/27»), под плитками плашка «Сезон 2026/27 · 1 авг 2026 — 31 июл 2027» с пояснением.
4. **«Любимые чемпионаты»:** турниры по убыванию числа прогнозов; доля %, количество и полоса (лидер — насыщенный sage).
5. **«Самый удачный исход»:** прогноз с максимумом очков — лига, дата, матч, рынок и событие, вероятность модели, коэффициент, очки.
6. **«Самые частые события»:** табы по категориям — Исходы, Тоталы, Фора, Угловые, ЖК; внутри топ-5 типов событий: число прогнозов (с полосой) и процент угаданных (sage ≥ 55%, coral < 45%).

Мобильный: плитки рейтинга 2×2, блоки в одну колонку, табы категорий скроллятся по горизонтали, колонки «Прогнозов» / «Угадано» сжимаются.

## Состояния

| Состояние | Поведение |
|-----------|-----------|
| Неизвестный id (или нечисловой сегмент, например ник) | 404 (стандартная страница Laravel; общий экран 404 — по [not-found.md](not-found.md)) |
| Нет угаданных прогнозов | «Пока нет угаданных прогнозов» в блоке удачного исхода |
| Нет прогнозов в категории | «Пока нет прогнозов в этой категории» |

## Определение сезона

Период «Сезон» — единый **сезон рейтинга платформы**: с 1 августа по 31 июля (например, «Сезон 2026/27 · 1 авг 2026 — 31 июл 2027»). Он не зависит от сезонов чемпионатов (РПЛ, ЛЧ и т. д.): «Сезон рейтинга действует с 1 августа по 31 июля и не зависит от сезонов чемпионатов». Границы и подписи вычисляет `App\Support\RatingSeason` по дате (1 августа — уже новый сезон, 31 июля — ещё старый); тот же хелпер использует `/leaderboard`, подробнее — [leaderboard.md](leaderboard.md).

## Данные и контракт

Контроллер: `UserProfileController@show`, мок-сборка — `App\Support\MockUserProfile`, общий мок рейтинга с `/leaderboard` — `App\Support\MockLeaderboard` (место и очки в профиле совпадают с таблицей).

Откуда берётся id:

- **Зарегистрированные пользователи** — `users.id`, ник — `users.name`, дата регистрации — `created_at`.
- **Моковые игроки** рейтинга — стабильные id `1 000 000 + порядковый номер` в `MockLeaderboard::PLAYERS` (`1000000` … `1000011`; порядок в массиве не зависит от места в рейтинге). Диапазон заведомо выше `users.id`, поэтому id не пересекаются. Когда моки уйдут, диапазон просто перестанет использоваться.

Маршрут принимает только цифры (`whereNumber`); любой другой id, а также нечисловой сегмент — 404.

Props `Users/Show`:

| Prop | Содержимое |
|------|------------|
| `profile` | `id`, `nick`, `registered_at`, `registered_label`, `is_me`, `rank`, `points`, `total_players` |
| `season` | текущий сезон рейтинга: `label` («2026/27»), `title`, `range`, `start`, `end`, `hint` |
| `ratings[]` | по периодам `week` / `month` / `season` / `all_time`: `rank`, `points`, `picks`, `correct`, `accuracy`, `caption` (для `season` — «2026/27», иначе `null`) |
| `championships[]` | `id`, `name`, `picks`, `share` (сумма `picks` = прогнозов за всё время) |
| `bestPick` | `match`, `league`, `market`, `event`, `date_label`, `probability`, `odds`, `points` |
| `frequentEvents[]` | категория: `id` (`results` / `totals` / `handicap` / `corners` / `yellows`), `label`, `total`, `items[]` (`name`, `count`, `accuracy`) |

Цифры детерминированы от id: один игрок всегда показывает одно и то же (в том числе при смене ника).

## Заготовка под `/me`

Шаблон `Components/UserProfile.vue` не знает про маршрут и принимает тот же набор props. Для `/me` достаточно отдавать из `MeController` ту же структуру (`profile.is_me = true`) и рендерить компонент внутри `Profile/Show` вместе со списком picks из [profile.md](profile.md). Место/очки/плитки/блоки для своего профиля переиспользуются без правок.

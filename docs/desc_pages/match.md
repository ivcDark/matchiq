# Страница матча

**URL:** `/matches/{id}`  
**Статус:** MVP (ядро продукта)  
**Inertia:** `Matches/Show`

## Зачем страница пользователю

За минуту понять, какие события вероятны в этом матче (оценки модели 0–100), прочитать короткий AI-прогноз хода игры и — при желании — выбрать **одно** событие в рейтинг до старта. Это главный экран MatchIQ: сюда должен попадать почти каждый визит.

## Что на экране

### Иерархия (сверху вниз)

1. **Шапка / навигация назад:** «← Матчи» + бренд; ссылки рейтинг / вход / профиль как на главной.
2. **Карточка матча (заголовок):**
   - хозяева — гости;
   - дата, время, лига (РПЛ);
   - статус: ожидается / идёт / завершён;
   - счёт — если матч идёт или завершён.
3. **AI-превью матча** (2–4 предложения): как может пройти матч. Не список факторов «почему p=72». Подпись вроде «Краткий прогноз модели» — без обещания гарантии.
4. **Фильтры событий** (один активный):
   - Лучшие — высокий p;
   - Худшие — низкий p;
   - Популярные — по выборам пользователей.
5. **Список событий** — основной блок:
   - название события / варианта (например «Обе забьют — Да»);
   - вероятность **0–100** крупно и однозначно;
   - для авторизованных до kickoff: кнопка/состояние «Выбрать» / «Выбрано»;
   - для гостей: при попытке выбрать — мягкий CTA на вход.
6. **Подсказка рейтинга (одна строка):** «1 событие на матч · больше баллов за смелый верный выбор (низкая вероятность)».

### Состояния матча

| Статус матча | Вероятности | Pick |
|--------------|-------------|------|
| Ещё не начался | Актуальный снимок (может обновляться до kickoff) | Можно выбрать / заменить |
| Идёт | Read-only снимок на момент kickoff | Закрыт |
| Завершён | Снимок + отметка, какие исходы зашли | Закрыт; у пользователя — результат его pick |

### Состояния UI

| Состояние | Поведение |
|-----------|-----------|
| Loading | Скелетон шапки матча + 4–6 строк событий |
| Empty (модель ещё не посчитала) | Честно: «Вероятности пока считаются» / «Нет событий для матча»; без фейковых чисел |
| AI-текст отсутствует | Скрыть блок или «Прогноз скоро появится» — не пустой карточный placeholder |
| Error | «Не удалось загрузить матч» + «Повторить» + ссылка на `/` |
| 404 матча | Как [not-found](not-found.md) или inline «Матч не найден» |
| Уже есть pick | Подсветка выбранного события; остальные — «заменить выбор?» до kickoff |
| После резолва | У выбранного: успех / промах + начисленные баллы |

## Что можно сделать

- Вернуться к списку матчей.
- Переключить фильтр событий (лучшие / худшие / популярные).
- **Авторизованный, до kickoff:** выбрать одно событие в рейтинг; **заменить** выбор до старта (по умолчанию MVP: замена разрешена).
- **Гость:** смотреть всё; при выборе — редирект/модалка на `/login` (с возвратом на этот матч).
- Перейти в рейтинг / профиль / регистрацию из шапки или CTA.

## Кто видит

| Роль | Доступ |
|------|--------|
| Гость | Полный просмотр вероятностей и AI-текста; pick недоступен без входа |
| Авторизованный | + действие выбора / замены до kickoff; видит свой текущий pick |

## UX-заметки

- Экран должен быть **сразу понятен** без обучения: крупные числа 0–100, короткие названия событий, один главный CTA на событии.
- **Мобильный first:** фильтры — горизонтальный сегмент/табы; список событий — вертикальный, без широких таблиц.
- На событии — **только вероятность**, без блока «почему» и без фактор-листов.
- **Не класть на экран:** полные составы, H2H-таблицы, live-таймлайн, графики для аналитиков, несколько picks, букмекерские коэффициенты, рекламные оверлеи.
- Не обещать «гарантию» в копирайте; вероятности — оценка модели.
- После kickoff UI не должен выглядеть «сломанным» — явно «выбор закрыт», вероятности как снимок.

# Главная / матчи

**URL:** `/`  
**Статус:** MVP  
**Inertia:** `Matches/Index`

## Зачем страница пользователю

Точка входа: выбрать лигу (или увидеть, что остальные «скоро»), за секунды увидеть матчи **активной** лиги и перейти к вероятностям. Страница не «лендинг с маркетингом», а рабочий каталог матчей с коротким объяснением ценности для новичка.

## Что на экране

### Иерархия (сверху вниз)

1. **Шапка:** бренд MatchIQ; ссылки «Рейтинг», «Войти» / «Регистрация» (гость) или «Мои выборы» + выход (авторизованный). Опционально — компактный индикатор/дубль текущей лиги (название), если пикер на странице ушёл из первого экрана при скролле.
2. **Короткий value-блок (1 строка + подсказка):** например «Вероятности событий по матчам» и одна фраза: «Откройте матч → события 0–100 → выберите одно в рейтинг». Без hero-маркетинга, статистики и промо-карточек. Не привязывать копирайт жёстко к одной лиге.
3. **Переключатель / пикер лиг** (обязательный блок MVP):
   - список **топ 5–10** лиг/турниров (группировка по стране — желательна, если помогает сканировать: например «Россия · РПЛ», «Англия · Premier League»);
   - **активные (live)** — кликабельны; при выборе фильтруют список матчей ниже;
   - **неактивные («скоро»)** — видны, visually disabled / с бейджем «Скоро»; тап не открывает матчи (можно лёгкий toast/tooltip «Лига в разработке»);
   - по умолчанию выбрана первая живая лига (для триала — **РПЛ**);
   - отдельный URL `/leagues` **не нужен**: пикер — секция главной.
4. **Переключатель периода:** Сегодня / Ближайшие / Завершённые (минимум; по умолчанию — «Ближайшие» или «Сегодня», если есть матчи). Период относится к **выбранной активной** лиге.
5. **Список матчей** (основной контент, только активная лига):
   - хозяева — гости (или логотипы + короткие имена);
   - дата и время kickoff;
   - статус: ожидается / идёт / завершён;
   - опционально компактно: счёт, если матч идёт или завершён.
6. **Футер лёгкий:** ссылка «Как это работает» (когда страница появится) или та же одна фраза-правило рейтинга.

### Состояния

| Состояние | Поведение |
|-----------|-----------|
| Loading | Скелетон пикера лиг + списка матчей (3–5 строк), не пустой белый экран |
| Empty (нет матчей за период в выбранной лиге) | Текст «На этот период матчей нет» + предложить другой период |
| Выбрана / тап по «скоро» | Список матчей не меняется на чужую лигу; подсказка «Скоро» |
| Нет ни одной активной лиги | Редкий кейс: честное «Матчи скоро появятся» — не фейковые матчи |
| Error | Короткое «Не удалось загрузить матчи» + кнопка «Повторить» |
| Offline / медленная сеть | Тот же error/retry; не зависать на бесконечном спиннере |

## Что можно сделать

- Выбрать активную лигу в пикере (и увидеть, какие лиги ещё «скоро»).
- Переключить период (сегодня / ближайшие / завершённые) для выбранной лиги.
- Открыть матч (тап/клик по строке → `/matches/{id}`).
- Перейти в рейтинг, вход, регистрацию, профиль (из шапки).
- Выйти из аккаунта (если авторизован).

## Кто видит

| Роль | Доступ |
|------|--------|
| Гость | Полный просмотр лиг и списка; CTA в шапке на вход/регистрацию |
| Авторизованный | То же + ссылка на `/me` |

## UX-заметки

- **Мобильный first:** пикер лиг — горизонтальный скролл чипов/сегментов или компактный select по странам; список матчей на всю ширину, крупные тап-зоны, без плотных таблиц.
- Главная должна **сразу** вести к ценности: активная лига и матчи видны без длинного intro.
- **Архитектура UI:** не хардкодить «только РПЛ» в копирайте и разметке; данные лиг (id, страна, название, `status: live | soon`) приходят с бэка — фронт рендерит активные и disabled одинаковым паттерном.
- **Не класть на экран:** отдельный тяжёлый каталог лиг, таблицу чемпионата, новости, «топ событий сегодня» (пока не доказана польза), сложные виджеты статистики, баннеры, карточный коллаж, несколько конкурирующих CTA.
- Пикер лиг — заметный, но **вторичнее** списка матчей: не превращать первый экран в витрину флагов. 5–10 пунктов достаточно; остальные лиги не раздувать.
- Бренд — заметный в шапке; value-блок не перекрикивает бренд длинным заголовком.

## Связи с другими страницами

- → `/matches/{id}` — основной переход (матч принадлежит лиге; лига видна на карточке матча).
- → `/leaderboard`, `/login`, `/register`, `/me`.
- ← возврат с матча, 404, auth-страниц («к матчам»); желательно сохранять выбранную лигу в query/state при возврате.
